Shadow Bargains Implementation Plan

Prepared June 2, 2026. This is the build plan for replacing the current static reference page with a single local-first application for players and DMs.

Build Goal

Create one fast, fun, responsive Shadow Bargains app. It should keep the clarity and pixel-adjacent feel of the prototype, replace the problematic font, add the full rules reference, add generated imagery, and preserve local-only character and DM data.

Do not build separate docs pages. Rules, reference, character builder, play sheet, and DM tracker live inside one cohesive app.

Recommended Stack

  • Vite + React + TypeScript. The app state, filters, routes, reference data, and tracker controls are easier to keep correct as typed components.
  • CSS modules or plain app CSS. Keep the styling small. No UI component framework.
  • localStorage only. No backend, no account, no sync, no download flow.
  • ZzFX. Small opt-in interaction sounds.
  • web-haptics. Opt-in mobile haptics with silent fallback.
  • Pixelarticons. Use existing pixel-esque icons. Do not hand-draw icon SVGs.

Workspace Starting Point

  • index.html contains the existing full content and should be mined for rules, archetypes, Boons, Banes, and negotiation copy.
  • .research/shadow-bargains-design-research.html contains the design decisions and image generation rules.
  • .plans/prototype-reference.html contains the approved prototype direction.
  • .plans/prototype-mobile-top.png and .plans/prototype-desktop-top.png show the approved prototype layout direction.

Information Architecture

Route Purpose Required content
Home First introduction for players and DMs. Short inviting copy, generated home image, local-only reassurance, Start Character, DM Tracker, Reference.
Build Fast character creation. Name, look, drive, stats, archetype chooser, Boon chooser, Bane chooser, gear, bargain, bonds, notes.
Play Use the saved character at the table. HP, Defense, stat roll buttons, last roll, Boon, Bane, drive, notes, no scene pressure.
DM Track one creature or NPC locally. HP, max HP, Defense, attack, damage, special move, status, Interest, Patience, motivations, pitfall, leverage, notes.
Reference Rules inside the app, not a separate docs area. Quick reference first, then detailed rules, character creation, combat, negotiation, archetypes, Boons, Banes, search and filters.
Settings Feedback and local data controls. Sound toggle, haptics toggle, clear character, clear DM tracker, clear all local app data.

Navigation

  • Desktop and iPad: simple left rail or top plus rail, matching the prototype mood. Use Home, Build, Play, DM, Reference, Settings.
  • Mobile: fixed bottom nav is acceptable. If six items feel crowded after the font swap, keep Home, Build, Play, DM, Reference in the bottom nav and expose Settings through the top feedback controls.
  • Keep the app chrome stable. Tapping between views should not feel like loading a different site.

Reference Content Requirements

Quick Reference

  • Core roll: d20 + Might, Guile, or Will.
  • Difficulty targets: 10, 13, 16, 20.
  • Boons and Banes: roll two d20s, keep higher or lower, cancel one for one.
  • HP and Defense: HP is 10 + Might, Defense is 10 + Guile.
  • Turn: one major action and one minor action.
  • Social exit: every fight has a social exit, every negotiation has violent risk.

Detailed Reference

  • Stats and examples for Might, Guile, Will.
  • Character creation flow.
  • Actions and combat timing.
  • Attack, Defense, damage dice, critical hits, enemy HP bands.
  • Archetype details and prompts.
  • Full Boon and Bane descriptions.
  • Negotiation setup, argument roll table, end states, example NPC.

Typography Plan

  • Replace Pixelify Sans.
  • Use Silkscreen for the logo and large section headings only.
  • Use Atkinson Hyperlegible, or a native sans stack if loading fails, for body text, controls, numbers, and trackers.
  • Add a .numeric CSS class for HP, Defense, rolls, counters, and dice notation.
  • Verify on mobile that 2, 8, 12, 20, 2/5, and d20 are unmistakable.

Interaction Feedback

  • Sound and haptics are opt-in. The default state is off.
  • Use ZzFX for tap, select, success, error, and roll sounds.
  • Use web-haptics for tap, select, success, error, and roll events. Fall back silently.
  • No ambient audio. No repeating loops.
  • Respect prefers-reduced-motion. The app should still feel good with only color and focus feedback.

Implementation Sequence

  1. Scaffold Vite + React + TypeScript in the repo without deleting PRODUCT.md, DESIGN.md, .research, .plans, or existing assets.
  2. Create the typed content data files from current index.html.
  3. Build the app shell, route state, localStorage persistence, nav, top feedback controls, and responsive layout.
  4. Build Home, Build, Play, DM, Reference, and Settings views.
  5. Add sounds and haptics behind opt-in settings.
  6. Generate and wire the planned images.
  7. Run desktop, iPad-width, and mobile verification with Playwright screenshots.
  8. Remove obsolete prototype-only root artifacts if any remain.

Acceptance Criteria

  • Single app entry point, no separate docs experience.
  • Player character and DM tracker persist locally in the browser.
  • No downloadable character sheet flow.
  • No scene pressure UI or rules references.
  • Reference contains quick and detailed rules, not just a short summary.
  • All six archetypes and all 24 Boon/Bane entries are present.
  • Generated images are present, intentionally placed, and not text-bearing.
  • The numeral 2 is readable anywhere numbers matter.
  • Sound and haptics are off by default and opt-in only.
  • Mobile, iPad, and desktop screenshots show no horizontal overflow or incoherent overlap.
  • Keyboard focus is visible and controls have accessible labels.
  • No account system, sync, backend, ambient audio, cinematic hero page, or generic SaaS styling.
