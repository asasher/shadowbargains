Shadow Bargains Design Research

Prepared June 2, 2026. This records the decisions made while moving from a minimal rules page toward a local-first table companion app.

Current Direction

The product should be a single cohesive application for players and DMs. It should feel like a friendly pixel-adjacent game tool used between friends, not a grand occult product site. The app stays local in the browser, uses pleasant opt-in feedback, and keeps rules close to the table workflow.

Local only Mobile and iPad first Desktop responsive No downloads No ambient audio

Product Facts

  • Shadow Bargains is a fast d20 one-shot system for groups who know 5e but want something lighter.
  • Core mechanics are Might, Guile, Will, archetype, one Boon, one Bane, HP, Defense, damage dice, and structured negotiation.
  • The app should introduce the system to players, help them make a character quickly, then let them play from the same device.
  • The DM needs one local creature or NPC tracker with combat stats and negotiation stats.

Prototype Findings

Keep

  • Warm dark pixel-art-esque shell with simple borders and compact controls.
  • Home, Build, Play, DM, Reference, Settings as one app flow.
  • Opt-in sound and haptic buttons in the app chrome.
  • Local autosave status and no account or export language.
  • DM tracker as one focused creature or NPC, not a GM dashboard.

Change

  • Replace Pixelify Sans. At small sizes the numeral 2 can read like 8.
  • Remove scene pressure entirely. It was a placeholder and does not belong in the rules.
  • Move from prototype sample content to the full rule, archetype, Boon, and Bane content from index.html.
  • Add generated image assets and a clear reference section.
  • Keep the app calmer than the early cinematic visual probes.

Visual Direction

The chosen lane is cozy dark pixel-table companion: simple, tactile, readable, a little cursed, and not self-serious. It should look like something a group uses during a one-shot, not a collectible lore portal.

  • Palette: near-black warm charcoal, iron brown-gray surfaces, tarnished brass accent, oxidized green success, dried blood danger.
  • Texture: subtle pixel grid or tile rhythm is acceptable. Do not add haze, glass, or gradient decoration.
  • Cards: use only for functional groups such as trackers, rule chunks, archetypes, and pickers.
  • Motion: short state feedback only. No page-load choreography.
  • Copy: direct and friendly. Avoid pompous occult phrasing.

Typography

The prototype font should be swapped. The implementation should use a pixel-flavored display font only where it helps the game identity, and a highly readable UI font for body, controls, and numbers.

  • Recommended display font: Silkscreen for logo and major headings.
  • Recommended UI font: Atkinson Hyperlegible or a native sans stack for body, forms, stat labels, and all numeric values.
  • Numeric fields, HP, Defense, rolls, and counters must never use a pixel font unless visual testing proves the digits are unambiguous.
  • Test the strings 12, 20, 2/5, d20, Defense 12, and HP 8/12 on mobile before accepting the font choice.

Libraries

Use

  • lochie/web-haptics for opt-in haptics, with graceful fallback to navigator.vibrate where available.
  • ZzFX for tiny generated interaction sounds.
  • Pixelarticons for the pixel-esque icon set.

Avoid for first build

  • No constant ambient sound.
  • No large animation runtime unless a specific interaction needs it.
  • No downloadable or printable character sheet flow.
  • No account, sync, backend, or server storage.

Information Architecture

  • Home: first introduction to the system, local-only note, Start Character, DM Tracker, Reference.
  • Build: name, look, drive, stats, archetype, Boon, Bane, gear, bargain, bonds, notes.
  • Play: current character, stat rolls, HP, Defense, Boon, Bane, drive, notes.
  • DM: one creature or NPC with HP, Defense, attack, damage, special move, status, Interest, Patience, motivations, pitfall, leverage, notes.
  • Reference: quick reference at top, detailed rules below, archetypes, Boons, Banes, negotiation, searchable and filterable.
  • Settings: opt-in interaction sounds, opt-in haptics, clear local character, clear DM tracker, clear all local data.

Content Inventory

  • Use the complete archetype data already embedded in index.html: Stalker, Blade, Hex, Saint, Shade, Beast.
  • Use the complete 24 Boon and Bane entries already embedded in index.html.
  • Use the current quick-play rules, difficulty table, turns and actions, attack and damage, creation flow, character reference, and negotiation sections from index.html.
  • Remove all scene pressure copy from the new app. Some old Bane text mentions scene pressure and should be revised before shipping.

Generated Image Direction

Images should make the app feel like a pleasant indie table tool. They should not create a cinematic landing page or overpower the interface.

  • Style: hand-crafted pixel art, readable silhouettes, limited palette, warm dark tabletop mood.
  • No text, letters, numbers, logos, UI screenshots, or fake writing inside generated images.
  • No generic parchment, neon cyberpunk, glossy fantasy realism, blurred backgrounds, or gothic excess.
  • Use the same palette across all images: charcoal, brass, muted green, dried red, bone highlights.
  • Prefer clear objects and characters over abstract atmosphere.

Image Asset List

  1. Home banner: friends around a table with tiny cursed tokens, cozy pixel art, no readable text.
  2. Rules reference tile: open rule cards, dice, brass marker, small candle, no writing.
  3. DM creature tile: Candle-Jaw Bailiff, single readable NPC portrait, warm dark palette.
  4. Six archetype portraits: Stalker, Blade, Hex, Saint, Shade, Beast, square composition, consistent background.
  5. Boon token sheet: 12 symbolic tokens in one image, later cropped or used as a sheet.
  6. Bane token sheet: 12 symbolic tokens in one image, visually distinct from Boons without relying only on color.
  7. Empty character portrait: neutral silhouette or token used before a player chooses an archetype.
